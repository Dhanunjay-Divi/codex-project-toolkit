# Arena review

Use this when a consequential decision remains genuinely uncertain and competing approaches can be tested or checked. This is original Codex-native guidance inspired by [arena-skill](https://github.com/Jakeschincariol/arena-skill); it does not install or invoke Claude Code's `/arena` command.

Frame the decision, constraints, acceptance evidence and cost or time budget. Develop two materially different feasible proposals, with source or test support and explicit failure modes. If only one is feasible, explain why rather than inventing an opponent. When the request and available native concurrency permit it, let a separate reviewer challenge each proposal on the same rubric; use only the number of agents the work actually warrants. Keep file ownership and side effects bounded, and stop at the agreed budget.

Compare the proposals against the evidence, resolve objections with targeted checks, and report a recommendation plus remaining uncertainty. A vote, ranking or elegant argument cannot replace tests, security review, signed-artifact identity, hardware observation, human approval or the project's release gates. Do not merge, deploy or message anyone merely because a proposal wins.
